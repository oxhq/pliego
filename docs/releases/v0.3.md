# Pliego 0.3: a versioned document engine for Laravel

Pliego 0.3 moves the project from a command-shaped renderer to a discoverable,
versioned document engine. The native runtime, PHP bridge, and Laravel package
negotiate one exact API 2 tuple and either return a hash-bound document delivery or
a typed failure.

The current recommended patch is **v0.3.3**.

## Laravel outcome

```sh
composer require oxhq/pliego-laravel:^0.3.3
php artisan pliego:install
php artisan pliego:doctor
```

```php
use Illuminate\Support\Facades\Storage;
use Pliego\Laravel\Facades\Document;

$stored = Document::view('invoice', ['rows' => $rows])->store(
    path: 'invoices/42.pdf',
    disk: 'local',
);

return Storage::disk($stored->disk)->download(
    $stored->path,
    'invoice.pdf',
);
```

The Laravel package renders once, verifies the API 2 result, and streams the PDF to
the selected Laravel filesystem. Application storage and Pliego's retained
diagnostic jobs have separate lifetimes. A failed storage write cannot become a
success-shaped `StoredDocument`.

## The API 2 contract

`pliego --contract-probe` advertises exactly one profile-null tuple:

- input manifest v1;
- render request v1;
- render result v1;
- DocumentScene v2; and
- bundle manifest v1.

`pliego render-api2` accepts one canonical request from stdin while running inside
an exclusive cwd-v1 job root. It never fetches live network resources or discovers
host fonts. The caller materializes every authorized input byte, and successful
delivery binds the PDF, scene, resources, and bundle manifest by path, length, and
SHA-256.

API 1 remains available only as a deprecated migration boundary. Semantic,
accessible-PDF, and hostile-input profiles are not advertised.

## Benchmark evidence

The hosted comparator lane renders the published v0.3.3 native bundle and
version-locked adapter dependency graphs for dompdf 3.1.6 and Browsershot 5.4.0
with Puppeteer 25.8.0. The first common
correctness slice renders the same `minimal-static` input and passes one Poppler
oracle for every eligible target.

This is not yet a performance result. No speed, memory, or CPU ranking is published
until the targets run interleaved on one dedicated, identity-pinned Linux host and
the raw samples, full descendant accounting, host evidence, and generated report
are retained. The [benchmark methodology](../benchmarks/README.md) records this
boundary.

## Support boundary

Pliego is for trusted, application-owned documents. The current profile covers a
deliberately bounded set of pagination, table, font, paint, JavaScript-readiness,
and Canvas behavior. Unsupported paint and indeterminate capture fail closed rather
than publishing a partial PDF.

Pliego 0.3 does not claim:

- arbitrary web-page or cross-browser compatibility;
- safe execution of hostile or tenant-authored HTML;
- PDF/UA or tagged-PDF conformance;
- cross-platform byte determinism; or
- performance leadership.

Read the [support profile](../pliego/support-profile.md) before selecting a
production document family.
