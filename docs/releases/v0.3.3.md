# Pliego v0.3.3

Pliego 0.3.3 is the API 2 publication-durability patch for the public 0.3 line.

## What changed

- API 2 now durably flushes the staged `resources` directory after writing its
  content-addressed files.
- The staged `delivery` and `diagnostics` roots are durably flushed before their
  atomic promotion into the accepted job root.
- Directory barriers use the same bound, identity-checked handles as the native
  publication path. Nested resource directories are created through Pliego's
  private-directory primitive on every supported platform.
- The native engine, PHP client, Laravel package, managed-runtime manifest, and
  reproducibility fixture advance together to 0.3.3.

The API 2 tuple, request/result schemas, and rendering profile are unchanged. API 1
remains deprecated and available for the existing migration window.

## Why this patch exists

The new hosted comparison gate measures each engine in a fresh delegated cgroup and
refuses to publish a sample while the measured process still owns dirty or writeback
pages. It reproduced a real v0.3.2 gap: artifact files were individually synced, but
the staged directory entries that named them were left to background writeback.
Depending on kernel timing, the same render could pass or retain one or two dirty
filesystem pages after the process exited.

This patch closes that native write set instead of weakening the measurement gate,
extending its timeout, or relabeling a patched build as v0.3.2. Comparative results
remain a separate evidence release and are not claimed by these notes.
