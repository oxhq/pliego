# Pliego v0.2.0

Pliego 0.2 moves the stable `render` command and the supported PHP/Laravel bridge
onto Pliego's controlled document transaction. A successful PDF is now tied to one
settled document generation; indeterminate readiness, capture, or publication fails
closed instead of falling back to a realtime render.

## What changed

- `pliego render` now uses the same controlled transaction as the
  `render-controlled` compatibility alias.
- The API 1 readiness bridge honors authored `defer`, `ready`, and `fail` state and
  retains the authored readiness payload in the publication evidence.
- Worker output is authenticated and staged privately before publication. Typed
  failures cannot publish a success PDF or success-only artifact tree.
- Native packages cover Linux x86_64, Windows x86_64, macOS Intel, and macOS Apple
  Silicon. The release also carries an exact generated runtime manifest for the
  Laravel installer.

## Compatibility and boundaries

The command name, API 1 result shape, and PHP rendering entry point remain stable.
Some requests that v0.1 could render without proving settlement now return a typed
failure. Diagnostic `--allow-partial-scene` behavior remains available on the stable
`render` spelling within its documented limits.

Failure result paths are locators for retained evidence, not a promise that every
failure creates an artifact directory. Engine API 1 remains the supported public
contract; the development API 2 probe still advertises no render capability.

This is a deterministic document renderer for the documented support profile, not a
general browser-compatibility or hostile-HTML sandbox claim. See the
[support profile](https://github.com/oxhq/pliego/blob/v0.2.0/docs/pliego/support-profile.md)
and
[threat model](https://github.com/oxhq/pliego/blob/v0.2.0/docs/security/threat-model.md)
for the exact boundaries.
The release does not claim byte-identical output across operating systems. macOS
Intel bundles are unsigned and Apple Silicon bundles are ad-hoc signed; neither is
Developer ID signed or notarized.

## Packages

The native release was promoted from one successful 13-artifact package run. After
the native assets became public, the PHP split repository was tagged and its v0.2.0
package was verified on Packagist. The Laravel split repository was then tagged; it
requires exactly `oxhq/pliego-php` 0.2.0 and carries the `release_ready: true`
`runtimes.json` generated from these exact native archives. The non-finalized
manifest in the monorepo source tree is not publishable.

```sh
composer require oxhq/pliego-php:^0.2.0
composer require oxhq/pliego-laravel:^0.2.0
```

Both v0.2.0 Composer packages are published on Packagist.
