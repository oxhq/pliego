# Pliego v0.4.0

**Status: unreleased.** The native engine and both SDK source packages prepare
version 0.4.0; the public recommendation remains v0.3.3. The managed-runtime
manifest remains `release_ready: false` until native promotion supplies the exact
four-platform archive identities. No 0.4.0 public installation is claimed here.

## Candidate scope

This release targets dependable API 2 business documents without combining the
semantic/accessibility architecture into the same milestone. It retains the
profile-null API 2 tuple, existing schema versions, supplied offline assets and
request-only page geometry. API 1 stays deprecated and available for migration.

- Original app-unit geometry is preserved for narrow URI links, ordinary solid
  borders/colors, page-owned root colors and solid table-track backgrounds.
- Collapsed tables admit an entirely nonpainting profile, bounded uniform
  visible borders and full/partial horizontal rules. Repeated headers retain
  exact page transforms. Headerless multipage visible borders, rowspans in the
  collapsed-grid path and arbitrary mixed styles remain excluded; cross-page
  rowspan continuation is still unsupported generally.
- Page-root fixed Flow text is realized separately for each page, including
  decimal physical `counter(page)` and `counter(pages)`. This is not a general
  CSS counter or fixed-layout implementation; footer space remains authored.
- Exact zero-area backgrounds and zero-font-size text can be absent ink without
  deleting the positive-size barcode bars or descendants around them.
- The Laravel SDK accepts maintained Laravel 12/13 dependency ranges. Both SDKs
  preserve the existing API 2 contract; the PHP page adapter also accepts exact
  integer app-unit tuples such as `67351x47622au`.

The [support profile](../pliego/support-profile.md#unreleased-040-candidate),
[table boundary](../pliego/paged-table-compatibility.md),
[fixed-content profile](../pliego/paged-fixed-content.md) and
[nonpainting contract](../pliego/nonpainting-content.md) define the exclusions.
No broad CSS, API 2 Chart.js, accessible PDF, hostile-input sandbox or
cross-platform byte-identity claim follows from these additions.

The [dependency advisory assessment](../security/dependency-advisories.md) records
the native RSA timing-side-channel restriction, exact wnaf applicability exception,
workspace XML-tool findings and remaining maintenance debt. The candidate is not
advisory-free. Keep private signing/decryption keys and private-key operations
outside document JavaScript; green CI with documented exceptions is not a security
fix or an independent security audit.

## Evidence required before publication

The selected corpus consists of a repaired Invobook invoice, a 300-entry Aureus
general ledger and a one-page Aureus manufacturing work order with three Code128
barcodes. Every shared application/template/font adaptation stays recorded beside
the original baseline. Internally operated external code is not independent
adoption, and one-page manufacturing coverage is not a long operational report.

Before promotion, require complete candidate-specific document and visual
acceptance, real SDK storage/readback, the declared Linux operational recipe and
desktop integration, and the four-platform package matrix. The bounded
[native consumer checks](../pliego/native-consumer-checks.md) cover actual API 2
caller deadlines, forced termination, local storage faults and concurrent queues;
their source-package runs do not substitute for public Composer installation.

Correctness-qualified numeric comparisons must retain all three repeats, all
attempts and per-family/provider denominators. Invobook's incumbent is Browsershot
5.0.5; Aureus's is dompdf 3.1.6. Fresh-process renderer timing is separate from
application generation and SDK/storage proof. Failed or unsupported documents
never become speedups, and the old v0.3.3 minimal-static publication remains a
separate immutable historical reference. No candidate timing results are claimed
by these preparatory notes.

Native promotion, finalized Composer archives, exact public tags/Packagist
references, upgrade/rollback and a fresh public-only consumer remain mandatory.
Follow the [ordered release procedure](README.md); do not replace a failed public
tag or archive. Semantic/accessibility work remains the 0.5 intention, professional
operational support 0.6, and independent-adoption/final-contract evidence gates 1.0.
