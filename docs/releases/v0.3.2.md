# Pliego v0.3.2

Pliego 0.3.2 is the Windows private-job compatibility patch for the public API 2
release line.

## What changed

- The PHP API 2 client now establishes a protected, current-user-only full-control
  DACL before asking Windows to confirm the job-root owner. This supports valid
  application storage trees where the current user inherits Modify access without
  the separate right to set object ownership.
- A Windows regression test creates that exact Modify-only parent boundary. It
  proves API 2 can create and verify the private runtime root while retaining its
  strict final DACL.
- The native engine, PHP client, and Laravel package advance together to 0.3.2 so
  the managed-runtime version and exact Composer dependency remain aligned.

The API 2 tuple and rendering semantics are unchanged. API 1 remains deprecated
and available for the existing migration window.

## Why this patch exists

Pliego 0.3.1 passed release CI and ordinary Windows temporary-directory tests, but
a fresh public Laravel consumer installed on an NTFS volume with inherited Modify
permissions exposed an ordering defect. `icacls /setowner` requires ownership
rights even when assigning the already-current owner, so running it before the
owner-only full-control grant failed with Windows exit 5. The corrected ordering
keeps the final security boundary unchanged and makes the supported storage shape
work.

## Release evidence

The patch is complete only when the exact native v0.3.2 tag has successful package
matrix and promotion evidence, GitHub marks v0.3.2 latest, both Composer packages
resolve v0.3.2 from their exact immutable tags on Packagist, and a fresh public-only
Windows Laravel consumer passes install, doctor, render, storage retrieval, and
typed-failure checks without a source checkout or `PLIEGO_BINARY` override.
